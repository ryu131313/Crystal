# Drops as real tables (plan)

Written 2026-10-21. **Status: phase 1 done 2026-10-21 (decisions D1-D7 confirmed as written; notes at the end); phase 2 not started.** Lean: two phases, one smoke check each, at most a couple of Opus 5.5 medium-effort subagents per phase (an auditor or builder at the start, one reviewer at the end). No time gates: a phase is done when its checks pass. Rules: `AGENTS.md`, `Knowledgebase/Server/server.md` (§3.2 threading, §3.4 persistence, §4.3 fields, §5.2 logging), `Knowledgebase/Client/client.md` only if a packet changes (none planned).

## Where things are today (after roadmap P7, commits `1d1b2403`..`ef68ceb9`)

- **All system data and design files live in `SystemData.db`** (SQLite, next to `Server.exe`; one writer thread, `Server/MirEnvir/Storage/`). `Server.MirDB` and the files under `Envir\Drops` are import sources only; the server no longer reads them. Runbook §10 covers backups, restore and rollback.
- **Drops today are "lines in a table":** `drop_lines (name, position, line_kind, chance, sep, item_index, item_name, gold, rest, text)` plus `design_files` (one row per former file, with its line ending). Typed lines carry an **item Index** link; anything else (comments, blanks, `{ }`, `#INSERT [file]`, odd spacing, 8,530 lines naming items that don't exist) is kept verbatim in `text`. Code: `Server/MirEnvir/Storage/Design/DesignTexts.cs`, `DesignTextFormats.cs` (`DropFormat`), `DesignFiles.cs` (path facade, in-memory cache).
- **The game still parses text:** `DesignFiles.ReadAllLines` renders the rows back to the old text and `DropInfo.Load` / `FromLine` / `ParseGroup` / `ParseInsert` (`Server/MirDatabase/MonsterInfo.cs` ~308-510) and `DragonInfo.LoadDrops` (`Server/MirDatabase/DragonInfo.cs` ~88) parse it.
- **Who loads drops:** `Envir.ReloadDrops` (Envir.cs ~6670-6710: per monster `Drops\<DropPath or Name>.txt`; fishing `00Fishing`..`18Fishing` (type = number); `00Awakening`, `00Strongbox`, `00Blackstone`, names in `Settings.cs` ~59-62); `DragonInfo.LoadDrops` (`DragonItem.txt`, lines carry a level 1..`MaxDragonLevel`); NPC `DROP` action (`NPCSegment.cs` ~1140 parse, ~4420 run: `DropInfo.Load(drops, "NPC", path, 0, false)` on every use, game thread); LiveDb monster drop reload (`Server/WebAdmin/LiveDb/LiveDbHooks.cs` ~27-36). Callers of ReloadDrops: StartEnvir, SMain menu, GM `RELOADDROPS`, web `ServerControlRoutes` ~257.
- **Who edits drops (all text):** web Scripts editor root "drops" (`Server/WebAdmin/ScriptFiles.cs`), drop class toggle (`ScriptRoutes.PostDropClassToggle` ~525), rename propagation (`GameData/GameDataRename.cs`), script validator (`ScriptValidation.cs`, drop + DragonItem kinds); WinForms `DropBuilder/DropBuilderForm.cs`, `ConfigForm.cs` drop toggle (~265), `Database/ItemInfoFormNew.cs` / `MonsterInfoFormNew.cs` rename propagation.
- **Game semantics to keep:** a monster without `DropPath` uses `Drops\<Name>.txt`, with one uses `Drops\<DropPath>.txt` (several monsters may share one); `#INSERT [sub]` appends `sub`'s lines at the end; groups `1/N GROUP[*|^]` + `{ ... }` nest (`*` random, `^` first); `Q` = quest required; `Gold` amount > 0; chance is `1/N` (the numerator is ignored); after loading, the list is sorted with gold last, then by item type; unresolved lines are logged (`CouldNotLoadDropLine`) and skipped.
- **Tools:** `tools/MirDbExport` (`check-files`, `import-files`, `export-files`, `export-binary`); tests `Server.Persistence.Tests/DesignStoreTests.cs`, `SqliteStoreTests.cs`, `tools/MirDbExport.Tests/StoreCommandsTests.cs`; `tools\verify.ps1`; scratch servers `tools\start-scratch-server.ps1` (a copy of the live data in `%TEMP%\mir2-p73-soak\run` was used for P7; rebuild a fresh copy from `Build\Server\Release` read-only, never write `Build\`).

## Decisions (recommended; confirm at the start of phase 1)

| # | Question | Recommendation |
|---|---|---|
| D1 | Who owns a drop list | `drop_lists (id, kind, monster_index, name, fishing_type)`. Kinds: `monster` (a monster without DropPath, linked by **monster Index**, so renames are safe), `named` (a DropPath list shared by name, NPC `DROP` lists, `#INSERT` targets, anything not tied to one monster), `fishing` (0..18), `awakening`, `strongbox`, `blackstone`, `dragon` |
| D2 | `#INSERT [sub]` | Keep sharing: an `include` row pointing at the included list's id, expanded at load exactly as today (appended at the end). No copying |
| D3 | Comments and section headers (`;Weapons`) | Phase 1 keeps them as `note` rows (needed for the text round trip while the text editors still exist). Phase 2: a header comment becomes the `category` of the rows below it; other comments go (kept in the `export-files` archive taken before phase 2) |
| D4 | The 8,530 lines naming missing items | Keep as `disabled` rows with their original text, shown greyed in the grid with a "delete all disabled" action. Nothing is dropped silently |
| D5 | Groups | `parent_id` (+ `position` within the parent) instead of braces; `group_mode` '' / '*' / '^' on the group row |
| D6 | Text editing of drops after phase 2 | Gone: the Scripts editor hides the drops root (or shows it read-only, rendered); DropBuilder, the drop class toggles and drop rename propagation are retired or rewired to the tables. Text in/out stays possible through `MirDbExport export-files` / an import command |
| D7 | Packets / client | No change: the client never sees drop lists |

## Phase 1: tables, conversion, the game reads rows

**Goal:** drops are rows the game loads directly; every existing editor keeps working unchanged (they still see text, rendered from the new tables).

**Work:**
1. **Schema** (new tables in `SystemData.db`, added by `SqliteWorldFile.Migrate` like the other design tables): `drop_lists` (D1) and `drops (id, list_id, parent_id, position, kind ['item','gold','group','include','note','disabled'], chance, item_index, quest, gold, group_mode, dragon_level, include_list_id, text)`. Item and list references are Index / id links. Keep `drop_lines` until the conversion is proven, then drop it in the same phase.
2. **Conversion** (one transaction, on store open, idempotent via a `meta` marker, with a `Pre-drops <time>.bak` VACUUM backup first, like the RespawnIndex repair): walk the existing `drop_lines` per file, map the file name to an owner (D1: `<MonsterName>.txt` without DropPath → that monster's Index; fishing / awakening / strongbox / blackstone / `DragonItem.txt` by name; everything else `named`), braces to `parent_id`, `#INSERT` to `include` rows, unresolved typed-looking lines to `disabled`, comments / blanks to `note`. Log counts per kind.
3. **Loader:** build `List<DropInfo>` / `GroupDropInfo` / dragon level lists straight from the cached rows (a new `DropTables` class next to `DesignTexts`, same in-memory cache rule: the game thread never queries the store). `DropInfo.Load(list, name, path, type, create)` keeps its signature and switches to the rows when the store is active (so ReloadDrops, the NPC `DROP` action, LiveDb hooks and the special lists change in one place); keep the same sort, the same `Type` values, the same "missing file" defaults (create the default note rows), and the same `CouldNotLoadDropLine` log for disabled rows.
4. **Text compatibility for the editors (until phase 2):** route the drops kind of `DesignFiles` to render a list's rows as the old text and parse saved text back into rows (`note` / `disabled` keep text verbatim, so the round trip stays exact). The Scripts editor, DropBuilder, toggles and rename propagation then need no change in phase 1.
5. **Tooling:** `MirDbExport check-drops <folder>`: for every list on a copy of the live data, build the drop lists the old way (render text + `DropInfo.Load` parse) and the new way (rows) and compare them structurally (chance, item index, gold, type, quest flag, group mode and nesting, dragon level). Must be 0 differences. `export-files` keeps writing the drop text files.

**Tests and smoke check:** `Server.Persistence.Tests`: conversion of a synthetic drop set (every line kind, a nested group, an include, a DropPath shared by two monsters, a dragon file, fishing types, a missing item), loader equivalence (old vs new lists equal), a monster rename keeps its drops, text round trip through the facade is byte-exact. **Smoke:** `check-drops` on a fresh read-only copy of the live data reports 0 differences; a scratch server on that copy starts, "Drops Loaded", and the same number of `Could not load Drop` lines as before; a GM-style `ReloadDrops` (web Reload Drops) works.

**Subagents (2):** an auditor at the start (read-only: every reader/writer of drops, confirm the semantics list above, list edge cases in the live data such as DropPath values shared by several monsters, include chains, odd group nesting); one reviewer at the end (threading of the cache and loaders, conversion data loss, equivalence).

## Phase 2: a grid editor, text editing retired

**Goal:** drops are edited as data in the web admin; the text editors for drops are gone or read-only.

**Work:**
1. **Game Data tables:** add `monsterdrops` as a **child table of monsters** in `Server/WebAdmin/GameData/GameDataRegistry.cs` (like `maprespawns` under maps), plus a `droplists` table for the non-monster lists (D1) with its own child grid. Columns: chance (shown as 1/N), item (lookup to items), quest, gold, group (parent), group mode, dragon level, category (D3), disabled flag. Validation: item exists, chance > 0, gold > 0 for gold rows, group nesting has no cycles.
2. **LiveDb:** classify the columns so an applied edit reloads that list in Main (the existing monster drop reload hook in `LiveDbHooks.cs` becomes "rebuild from rows").
3. **Frontend:** the Game Data grid already renders child tables (`Server.MirForms/wwwroot/admin/`, vanilla JS, `Server/WebAdmin/README.md`); add the drop-specific bits only: 1/N display, group indentation, a "copy drops from monster X" action (replaces copy-paste of files), "delete all disabled", and the drop class toggle as a grid action (it currently rewrites files).
4. **Retire text editing (D6):** hide the drops root in `ScriptFiles` (or make it read-only rendered text); remove drop handling from `GameDataRename` (Index links make it unnecessary); drop validator kinds for drops/DragonItem; WinForms: DropBuilder edits rows or is removed (decide in the phase; removing it is the lean choice, the web grid replaces it), ConfigForm's drop toggle calls the same toggle as the web action, Item/MonsterInfoFormNew stop propagating renames into drops.
5. **Cleanup:** drop the text compatibility path for the drops kind in `DesignFiles` (phase 1 step 4) except the render used by `export-files`; convert header notes to `category` (D3) after taking an `export-files` archive; update `server.md` §2.6, `Server/WebAdmin/README.md` (Game Data, Scripts), Runbook §10.

**Tests and smoke check:** `Server.WebAdmin.Tests`: the registry tables (insert / edit / delete a drop, group nesting, the copy action, validation errors, LiveDb classification); `check-drops` still 0 differences after the category conversion. **Smoke:** on a scratch copy, edit a monster's drops in the grid with LiveDb on, kill the monster in game (StressClient or a test account on the scratch server) or use Reload Drops, and see the change; restart and see it kept.

**Subagents (2):** a builder for the frontend grid pieces (only `wwwroot/admin/*` files, so no overlap with the main session's server work); one reviewer at the end.

## Phase 1 notes (2026-10-21)

- **Code:** `Server/MirEnvir/Storage/Design/DropTables.cs` (tables, cache, text facade, conversion `ConvertLines` run by `SqliteWriter` on open after the respawn fix, loaders `LoadInto` / `LoadDragon`); `DropInfo.TryParseLine` / `DragonInfo.DropInfo.TryParseLine` hold the line syntax once; the text loaders stay as `LoadFromLines` (store off, and `check-drops`' reference). `DesignTexts` routes the drops kind to `DropTables`; `DropFormat` only renders `drop_lines` for the conversion now.
- **Every row keeps its line** (`text`), so the text facade renders exactly; an item row substitutes a renamed item's current name. Phase 2's grid will need a canonical render for rows it creates without text.
- **Classification follows the game, not the 7.4 regex:** 323 typed-looking lines the regex left as text load in the game (`1/2 Gold 20000 LV1`, `2/1 Item Q`) and are typed rows; disabled = what the game logs (missing item, unreadable line, a first token shorter than 2 characters, which the text loader threw on). A disabled row's text is tried again at load (an item created later loads, as before).
- **#INSERT:** a list with includes is assembled from all its lists' lines at load, so a group left open at the end of one list still takes the next list's lines (exact old behaviour); self / cyclic includes are skipped and logged instead of looping forever; a missing target is logged instead of throwing. No live list has an `#INSERT` or a brace.
- **Lists are found by file name, as before; the owner is recorded, not followed.** `drop_lists.kind` / `monster_index` / `fishing_type` come from the name (`OwnerOf`) and are re-derived on every write and rename. A first version let a monster's list follow the monster's current name; the reviewer showed that breaks a file shared by several monsters (one with `Name.txt`, one with that DropPath), a rename the running world hasn't loaded yet (Reload Drops would create an empty default under the old name), and Index reuse. So in phase 1 a monster rename keeps its drops only through the web rename propagation (it moves the list; the moved list then belongs to the monster), as in 7.4. The WinForms editor never propagated drop renames (`MonsterInfoFormNew` has no drop code, contrary to the "Who edits" bullet above). **Phase 2:** bind drops to monsters by Index in `ReloadDrops` / the grid (D1), deciding shared lists explicitly.
- **Rollback safety:** the store's `schema_version` goes 2 → 3 when the writer opens it after the conversion, so a 7.4 build refuses the converted file instead of finding an empty `drop_lines` and creating empty default lists for every monster. This build still reads a 2 store, such as a restored older `.bak`, and converts it.
- **One list per name:** a save replaces any list of the same name, case-insensitively, in the store and the cache. This covers a game-thread default racing an editor create. Cache resets and loads are guarded by a generation counter.
- **#INSERT** follows the name in its line first, as the text loader did, and falls back to the stored `include_list_id` when no list has that name.
- **Live data (copy of 2026-10-21):** 1,640 lists (106 monster, 1,528 named, 2 fishing, 1 each awakening / strongbox / blackstone / dragon); rows item 60,853, gold 1,112, group 2, note 55,934, disabled 8,575. `check-drops`: 0 differences, 2 lists the old loader throws on (`00DiceItem`, `00GroupDiceItem`, loaded by nothing). Scratch server: converted once, drops loaded, same bad-line log as the old build on the same data, restart without reconverting.
- **Left as is:** the dragon text loader still sorts two gold rows of one level with a null item (NullReferenceException, Known defect); the row loader returns 0 there instead. `SMain`'s Reload Drops menu still calls `ReloadDrops` on the UI thread (Known debt).

## Rollback

- Phase 1: the conversion takes `Pre-drops <time>.bak` first; restoring it (Runbook §10) goes back to `drop_lines`, which the previous build reads. `export-files` writes text drop files at any time.
- Phase 2: the previous build still reads the phase-1 tables; text files via `export-files`.
