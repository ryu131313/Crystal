# Scene Lab UI review: feature windows (2026-10-15)

Scope: the untracked `WebClient/play/hud*.ts` feature windows (Awaken, Craft, Creature, Extras, Fishing, Friends, GameShop(+Data), Group, Guild, Hero, Inspect, Mail, Mentor, Merchant, Mount, Npc, NpcBox, Quests, Ranking, Refine, Relationship, Rent, Socket, Storage, Territory, Trade, Trust), `play/lab-data/*.json` and the `tools/publish-webclient.ps1` change. Shared infrastructure (hudWindow / hudDrag / hudTooltip / hudPopup / hudItems) is reviewed separately in `Review-Core.md`. Line numbers are from the working tree on 2026-10-15. Nothing was edited.

## Summary

**Update 2026-10-15 (same day):** the user approved fixing the Bugs section, the innerHTML points and the simple numeric mismatches; each bug and mismatch below carries a Status line. Features Crystal lacks were left as listed mismatches on purpose. `npx tsc --noEmit -p tsconfig.json` passes.

- The mocks are careful and mostly match the server formulas they cite (awakening odds and prices, refine formula, gem chance, craft roll, repair / special repair, mail postage shape, guild buff points, territory prices). No XSS today: all data-bearing text goes through `h()` / `textContent`; `innerHTML` is used for constant SVG only, with two exceptions that become XSS once real names flow in (Hero feed, Ranking guild shield).
- Real bugs are mostly state-consistency: closing a window by Esc bypasses its cancel logic (Trade), selections that keep pointing at a destroyed entity (Awaken, Socket), losing items / gold when the bag is full or a mode switches (Trade, Rent, Socket), empty-list crashes (Creature), a stale banner (Guild), "#0" ranks (Ranking).
- Several windows imply rules Crystal does not have; porting them as drawn would mislead (mail item slots without a stamp, add-only trade gold, friend requests, group loot rules / join requests / pass leader, fixed guild ranks, gifting in the game shop, quest accept / turn-in away from the NPC, hero revive from the window, recipes the server never sends).
- `lab-data` is correctly kept out of the public snapshot and holds no account / character / IP data. But the next publish will ship ~1.26 MB of lab modules (`js/play/lab.js` + all `js/play/hud*.js`) and the relay will `modulepreload` every one of them for every player.
- About 12 `setInterval`s start in constructors and run forever; several simulate (and change state, chat or HUD level) while their window is closed.

## Bugs ranked by severity

### High

1. **Publishing ships and preloads the whole lab (1.26 MB) for every player.** `tools/publish-webclient.ps1` (diff) excludes `play/lab.html` and `play/lab-data/`, but still copies every `WebClient/js/**/*.js`, so `js/play/lab.js` and the 60 `js/play/hud*.js` modules go public (the current public snapshot already has `js/play/lab.js`). `WebRelay/PageBuild.cs:102-104` adds a `<link rel="modulepreload">` for every module not under `tools/`, so each player downloads and compiles the lab mocks on page load. They also embed DB-derived data (`hudGameShopData.ts` is the live GameShop catalogue; harmless, players see it in game). Fix: in the publish script skip `js/play/lab.js`, `js/play/hud*.js` (or build the lab to a separate outDir via its own tsconfig), and have PageBuild preload only `main.js`'s import graph or skip `play/hud*` / `play/lab*`.
   - Status: **Fixed** by the coordinator: `tools/publish-webclient.ps1` now ships only `js/play/main.js` from `js/play` (not touched here).

2. **Trade: Esc / Shift+Esc / "Close all" do not cancel the trade.** `hudTrade.ts:241` hooks `cancel()` only to the title-bar cross; `HudWindow.hookKeys` / `closeAll` call `toggle(false)` (`hudWindow.ts:146,161`) and TradeMock does not override `toggle`. Scenario: offer 3 items, press Esc: the items stay out of the bag (they live in `mine[]`), the partner's queued timers stay alive and resume on reopen, and the lab reopen path (`shown()` with a non-empty log) continues the half-done trade. Crystal treats closing the trade window as `TradeCancel`. Fix: override `toggle` like `hudNpcBox.ts:144-147` and call `cancel()` when hiding.
   - Status: **Fixed** (`hudTrade.ts`): `toggle` is overridden, so every close path (cross, Esc, Shift+Esc, Close all) runs `abort()` (offer back to the bag, partner timers dropped); `cancel()` is just `toggle(false)`.

3. **Trade / NpcBox: `addToBag` leftovers are ignored, so items vanish when the bag is full.** `hudItems.ts:54` returns what did not fit; callers drop it: `hudTrade.ts:181` (returnOffer), `:283` (finish: their items), `:337` (take back), `hudNpcBox.ts:153` (giveBack), `:323` (disassembly loot). Scenario: offer an item, fill the bag from the Storage window, cancel the trade: the offered item is gone. Trade `roomCheck` runs at Confirm, but the bag can change in the 1.6-2.3 s before `finish()`. The server mails what does not fit (`PlayerObject.TradeCancel` -> `GainItemMail`). Fix: handle the leftover (mock "sent by mail" or refuse).
   - Status: **Fixed**: Trade `returnOffer` / `finish` / take-back and NpcBox `giveBack` / disassembly loot use `addToBag`'s leftover: take-back keeps what does not fit offered, cancel / finish report it as mailed (server TradeCancel / GainItemMail), `finish()` re-runs the room check and unlocks both sides like the server; NpcBox keeps an unfitting item on the altar.

4. **Awaken: a destroyed item stays selected for 1.8 s and can be awakened again; a second failure deletes a different item.** `hudAwaken.ts:229` removes `g` from `gear`, but `sel` is only reset in the 1800 ms timeout (`:234`); `blocked()` still returns "" for it, so with materials and gold the hold button (1200 ms) works. On another failure `this.gear.splice(this.gear.indexOf(g), 1)` runs with index -1 and removes the last entry (SealedHero). Same pattern in `hudSocket.ts:226-230` (gone piece stays `sel`, `why()` ignores `gone`). Fix: switch selection immediately and guard `indexOf(...) >= 0`.
   - Status: **Fixed**: Awaken `blocked()` returns "Destroyed" for an item no longer in `gear`, the splice is guarded, the 1.8 s reselect no longer assumes a non-empty list; Socket `why()` returns "Destroyed" for a gone piece and the reselect is guarded.

### Medium

5. **Rent: switching role drops the paid fee.** In renter mode each quick button calls `host.spend` (`hudRent.ts:186`); the role switch (`:150`) calls `reset()` which zeroes `fee` without `host.gain` (only Cancel refunds, `:196`). Scenario: "I rent", +50,000, "I rent out": 50,000 gold gone.
   - Status: **Fixed** (`hudRent.ts`): switching role while renting refunds the fee you paid in.
6. **Rent: the 3-items-out limit is only a note.** `hudRent.ts:151` sets `partnerCan = true` for the owner and `:194` only checks that, so with 3 active rentals you can still lock, confirm and get a 4th (the note at `:199` shows but nothing blocks).
   - Status: **Fixed** (`hudRent.ts`): Confirm is disabled (and its click ignored) for an owner with 3 active rentals.
7. **Socket bench: changing the socketed item deletes its jewels.** `hudSocket.ts:241` sets `sockets = [null, null, null]` without returning the socketed jewels to `this.jewels`. Scenario: socket Ruby of Fury into DragonSlayer, click TitanArmour(M): the ruby is gone.
   - Status: **Fixed** (`hudSocket.ts`): changing the socketed item returns its jewels to the bag.
8. **Creature: releasing the last creature crashes the window.** `hudCreature.ts:230` splices and sets `picked = 0`; with 4 releases `cur()` (`:129`) returns undefined, `render()` throws on `c.name` and `animate()` throws every 100 ms while open. Fix: empty state.
   - Status: **Fixed** (`hudCreature.ts`): `cur()` may be undefined; an empty stable shows a message and `animate` / `renderFeed` / `renderStone` skip.
9. **Ranking: picked player off the current board shows "#0".** `hudRanking.ts:217-218`: `picked` defaults to "GMRyu" (Warrior); on the Wizard board `all.indexOf(p) + 1` is 0, so the side card reads "#0 wizard rank". Fix: fall back to `all[0]` when `p` is not in `all`, or reset `picked` on board change.
   - Status: **Fixed** (`hudRanking.ts`): the profile card shows the picked player only when they are on the board, else its leader.
10. **NPC dialogue swallows number keys globally.** `hudNpc.ts:163-172` registers a capture-phase `keydown` that turns Digit1-9 into dialogue choices whenever the window is open (and Escape even when another window is in front). Crystal's belt keys are 1-6, so potions cannot be used while an NPC page is open. Limit to when the NPC window is the front window, or use a modifier.
   - Status: **Fixed** (`hudNpc.ts`): keys only while the NPC window is the front window; the number keys also need the pointer over it, so the belt keys keep working.
11. **Guild: Members page steals focus on every redraw.** `hudGuild.ts:366` focuses the search box after each `render()` (row click, sort, filter). With focus in an input, `HudWindow`'s Esc handler ignores the key (`hudWindow.ts:157`) and the search box `stopPropagation`s keys, so Esc / G no longer close the window after clicking a member. Focus only when the page is first opened.
   - Status: **Fixed** (`hudGuild.ts`): the search box is focused only when the Members page is opened from the side menu.
12. **Mail postage rounds the wrong way.** `hudMail.ts:332` uses `Math.ceil(gold / 1000) * 100`; the server floors (`PlayerObject.GetMailCost`, `Math.Floor(gold / 1000) * MailCostPer1KGold`). 1,500 gold costs 100 on the server, 200 in the mock. Insurance is per item `floor(Price() / 100 * 5)` on the server vs `ceil(total worth * 0.05)` (`:333`).
   - Status: **Fixed** (`hudMail.ts`): postage is `floor(gold / 1000) x 100`; insurance is `floor(worth / 100 x 5)` per attached item.
13. **NpcBox "Replace wedding ring" price is flat 125.** `hudNpcBox.ts:26,189` vs `PlayerObject.ReplaceWeddingRing`: `RequiredAmount x 10 x ReplaceWedRingCost`. `hudRelationship.ts:209` already does it right, so the two mocks disagree. `why()` (`:170`) also only checks "is a Ring"; the server also requires a wedding ring worn in RingL.
   - Status: **Fixed** (fee): `hudNpcBox.ts` charges `RequiredAmount x 10 x 125` and says so in the preview. **Not fixed**: the "wearing a wedding ring in RingL" check (the lab has no marriage state shared with NpcBox).
14. **Crafting stack-size cap is claimed but not implemented.** Header (`hudCraft.ts:9`) says the quantity is capped by stack size; `maxCraft` (`:136`) caps at 99. The server refuses `count > goods.StackSize / goods.Count` and `ingredient.Count * count > ingredient.StackSize`, and each ingredient must sit in one bag stack (`NPCScript.Craft`, NPCScript.cs:1263, 1312, 1363). Scenario: the default BugNecklace recipe shows "Can make N" > 1; the server accepts only 1. Gender criteria are shown but never checked (`:128-132`).
   - Status: **Fixed** (stack cap): `maxCraft` caps by the result's `StackSize / amount` and each ingredient's `StackSize / count` (items.json, else 1 for gear types). **Not fixed**: gender (no recipe on this server sets one, and the lab host has no gender); the one-stack-per-ingredient rule (the mock counts totals).

### Low

   - Status: **Fixed** (`hudGuild.ts`): the banner member count is refreshed in `render()`.
16. **Mentor simulation runs while closed and changes your level.** `hudMentor.ts:150,173`: in "As mentee" mode `myLevel++` on its own, diverging from the HUD level that `setLevel` feeds in; graduation can fire while the window is hidden.
   - Status: **Fixed** (`hudMentor.ts`): the simulation runs only while the window is open and never changes your level; as mentee, graduation is checked in `setLevel` (the HUD's level).
17. **NPC conversation log duplicates.** `hudNpc.ts:312` pushes the page text in `talkPane()`, which runs on every `render()` (Log toggle, Quests tab and back), and the typewriter replays each time.
   - Status: **Fixed** (`hudNpc.ts`): a page sequence number; a redraw of the same page neither logs it again nor replays the typing.
18. **Timers: `setTimer(key, label, 0)`** (documented as "0 seconds expires it", `hudExtras.ts:308`) sets `len = 0`, so `:438` computes `0/0` (NaN dash offset) and announces "time's up" (S.ExpireTimer should just remove it). Gone timers are only pruned from `list` on the next expiry (`:446`).
   - Status: **Fixed** (`hudExtras.ts`): `setTimer(key, label, 0)` removes the timer silently; expired timers are pruned when their fade-out ends.
19. **Fishing:** closing during a bite freezes `tick()` (`hudFishing.ts:154`), and on reopen the next tick reports "Too slow" at once.
   - Status: **Fixed** (`hudFishing.ts`): reopening during a bite gives the full reaction time again.
20. **Merchant cart "+"** has no cap (`hudMerchant.ts:193`) while a row click caps at `stack * 5` (`:178`).

21. **Refine uses float averages** where the server uses integer division (`hudRefine.ts:144-145` vs `PlayerObject.RefineItem`: `requiredLevel / itemAmount`, `orePurity / oreAmount >= refineStat / itemAmount`). Edge cases differ (avg purity 9.5 vs avg stat 9.6: server +15, mock 0).

22. **XSS once real data arrives:** `hudHero.ts:405` sets `innerHTML` from feed strings that interpolate the hero name; `hudRanking.ts:202` puts `name[0]` (guild name) into an SVG `innerHTML`. Safe with mock constants; do not port as is.
   - Status: **Fixed**: `hudHero.ts` feed entries are `[class, text, bold name]` drawn with text nodes; `hudRanking.ts` sets the shield letter with `textContent`. The other `innerHTML` uses in these files are constant SVG.

## Improvements

**Before porting, extract (these are duplicated across 20+ files, ~57 local copies):**
- Formatting / naming: `fmt`, `pretty`, class tag maps (`CLASS_TAG` / `CLS` / `CLS_SHORT` in Friends, Group, Ranking, Mentor, Relationship, Inspect), `svg` / `svgIcon`, grade colours (already in hudTooltip `GRADE`).
- Item lookups: Awaken, Inspect, Refine, Rent, Socket, Trust each build their own `items` map from `itemData()`; `hudItems.info()` already does this.
- Widgets: confirm-twice button ("Click again to ..." in Friends, Group, Guild, Mail, Quests, Creature), hold-to-confirm (Awaken, NpcBox), segmented control / chips / toggle switch / tabs (each window re-declares CSS for them), progress ring SVG (Craft, Creature, Mentor, Refine, Extras), confetti / sparks / shards (GameShop, Mentor, Relationship, Craft, NpcBox, Refine), fake-partner chat thread (Trade, Friends, Mentor, Relationship).
- One wallet: Trade (`MY_GOLD`), Merchant (`gold`), GameShop (`gold`) keep private gold while others use `host.gold()`; the port needs one source (account gold / credits from packets).
- One ticker: replace the constructor `setInterval`s (Creature 100 ms + 1 s, Fishing 80 ms, GameShop 5 s, Group 1.2 s, Guild 1 s, Hero 1 s, Mentor 2 s, Mount 100 ms, Npc 150 ms, Refine 1 s, Relationship 1 s, Trust 1 s) with the HUD's frame loop or a shared ticker that skips hidden windows. In the port the state comes from packets, so the simulations must stay in the lab layer.

**Window lifecycle:**
- Give `HudWindow` a `closed()` hook (or document overriding `toggle`, as NpcBox does) so every close path (cross, Esc, Shift+Esc, Close all) runs the same cleanup; Trade and Rent need it, NpcBox already has it.
- Keep a single "selected id" and resolve it per render (Awaken, Socket, Creature, Ranking, Mail, Friends all hold object references that go stale).
- Most windows rebuild their whole DOM on any change, then patch around the side effects (Hero `held`, Trust `hovering`, Relationship scroll restore, Guild re-focus, NPC typewriter replay). Splitting into regions that redraw independently (as Friends / Quests / Mail already do) would remove those workarounds before the port.

**UX:**
- Several windows let you act where Crystal requires an NPC (Quests accept / turn in, Hero revive, Mail collect; Territory already refuses a sale outside the estate). Show the NPC requirement rather than a working button, or the ported UI will promise actions the server refuses.
- Disabled buttons use `.dis` with `pointer-events: none`, so their `title` explaining why never shows; Territory's pattern (clickable, shows the reason) is better.
- 920-1000 px fixed widths: these windows will not fit the 1024 x 768 layout with the HUD scale below 1; plan a narrow layout.

**lab-data:**
- Contents checked: items (ItemInfo fields), maps (NPCs, exits, spawns, safe zones), monsters (name -> AI), recipes, territories. No account, character, IP, password or e-mail data. Excluded from the public snapshot by the new filter (correct), and the public relay serves only `publish/public` (`tools/start-public-webrelay.ps1:44`).
- Not git-ignored and no generator is checked in (the docs say "exported from a copy of the live Server.MirDB" / "the scratch DB reader"). If committed, the private repo gets live spawn / recipe data with no way to regenerate it. Either check in the exporter (it fits `tools/MirDbExport`) or git-ignore `WebClient/play/lab-data/` and document how to produce it.
